Rust S-Expression Phase 1 Corpus Measurement

Decision

The named-corpus performance and peak-memory harness is accepted as the Windows measurement baseline. It closes the implementation and local evidence portion of the Phase 1 corpus-measurement task. Release floors remain unratified until an independent Linux run reproduces the harness and the parser promotion review accepts explicit budgets.

Method

  • Three promoted inputs are pinned by corpus-relative path, byte length, file SHA-256, and the content-addressed corpus archive SHA-256.
  • Rack builds the test-only runner once in release mode, then invokes the executable directly so Cargo and compilation memory are excluded.
  • Each tier runs three isolated processes for parse-only and full semantic-roundtrip operations. The best time, median time, all raw runs, and maximum sampled peak RSS are retained in transient evidence.
  • Parse-only holds the source and one generic tree. Semantic roundtrip holds source, canonical output, both trees, and second output long enough for the parent sampler to observe their process peak.
  • Every roundtrip proves parse, build, reparse, tree equality, and byte-stable second output. The dependency-free sampler uses native process counters on Windows and /proc high-water marks on Linux.

Interpretation

Throughput is already useful, but full generic-tree memory is material. The large parse-only path peaks at about 7.4 times input size, while the two-tree oracle intentionally reaches about 16.7 times input size. This supports the existing architecture decision: the generic tree remains a compatibility and validation path, while promoted converters and typed readers must use selective spans or direct typed views rather than allocating the complete generic tree.

Retained Gates

  • Run the same hashed cases on Linux before ratifying floors.
  • Set budgets only in the parser architecture/promotion review.
  • Keep the measured selected-span sorting cost visible during budget ratification.
  • Measure path ownership and selector scaling separately.
  • Keep streaming-select, source-patch, and browser/WASM transfer as independent ledger tasks.
  • Do not authorize typed-model expansion until every Phase 1 dependency closes.
