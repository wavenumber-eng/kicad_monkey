Architecture Audit

  • kicad-monkey-core has no normal third-party dependency, platform API, FFI type, or package-owned unsafe code. Source views own spans and borrow caller bytes. Typed hot paths never build a generic tree for the complete file; selected forms are materialized only when their local semantics require it.
  • kicad-monkey-contracts contains TypeSpec-generated DTOs and depends only on Serde. Handwritten semantic validators sit beside generated structural types and prevent contradictory union states.
  • kicad-monkey-wasm is a thin operation adapter over core and contracts. Source and auxiliary request bytes are separate arrays. Large result payloads are returned out of band from small metadata envelopes; no base64 is used.
  • Invalid request JSON, identity, or platform-sized limit strings are transport failures and reject the call. Valid requests that encounter source, model, or resource failures return structured diagnostics and no partial output. This distinction is intentional and must remain stable for downstream wrappers.
  • TypeSpec is authoritative for every public operation in this slice. JSON Schema, Rust, strict Python/msgspec, and TypeScript projections are generated and checked for drift through Rack.
  • The workspace conforms to wn-dev-std 2026.8.12. The Rust structural ratchet, warnings-denied Clippy, rustfmt, complete Cargo tests, and real wasm32 execution pass. No provisional standards exception remains.

Copy And Artifact Evidence

WASM inputs are borrowed slices. Read operations serialize one result buffer. Edit and plot operations allocate the produced KiCad or JSON bytes plus a separate metadata buffer. Paired-output objects retain compatibility clone getters and also expose takeOutputBytes, which consumes the result and transfers ownership exactly once for large-output paths.

Locked release wasm32 builds before JavaScript glue, compression, or wasm-opt measure 292,798 bytes for sexpr, 409,815 bytes for footprint, 556,646 bytes for symbol, and 787,825 bytes with every default feature. The three operation families build independently; the default remains an all-operations development artifact.

Findings Requiring Disposition

  1. Closed — WASM artifact ownership and features. Cargo features sexpr, footprint, and symbol independently compile operation-shaped artifacts. Rack verifies every locked wasm32 feature build. If PCB or graph operations are selected after native parity, each receives its own feature or downstream-owned artifact rather than entering every build.
  2. Closed — large output ownership. Every paired edit or plot result exposes a tested consuming takeOutputBytes path. Repeated cloning is no longer the only supported browser API.
  3. Retained gate — Python integration. Generated Python contracts and Python-oracle parity are complete. PyO3 acceleration is optional work after native parity and is not required to approve this boundary.
  4. Retained gate — text and complete visual parity. Outline text remains behind FontBundle, Rustybuzz shaping-record, and outline-extraction gates. Phase 2 proves the non-text IR subset; it does not claim full SVG or text-render parity.
  5. Retained gate — platform matrix. Windows native and Node-hosted real wasm32 execution pass. The native Windows kicad-cruncher lane is the product critical path. Other native platforms and an actual browser are required only by later artifacts that claim support for them.
  6. Dispositioned scope: WASM and downstream adapters. Do not expand WASM while native reader/writer, plotter, compiler, CLI, and Rack parity remain open. Select concrete browser operations after native parity; downstream projects may package their own wrappers. pcb_a0, Viz, and ALX adapters are a separate downstream task and are not gates in this plan.
