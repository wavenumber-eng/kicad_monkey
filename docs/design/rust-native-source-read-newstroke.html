Rust native source reads and Newstroke geometry

Status: accepted issue #84 importer/Newstroke slice after independent review. This boundary exposes source-owned embedded resources, standalone-footprint members, and native KiCad Newstroke centerlines. Canonical PCB mapping, workspace path resolution, resource fetching, and application rendering remain downstream.

Embedded-resource ownership and payload states

EmbeddedFile is a borrowed source declaration whose EmbeddedFileOwner distinguishes the board, a board-embedded footprint by stable source index, or the standalone footprint. Filename, type, checksum, source range, and authored encoded-data size can be inspected without decoding or copying the payload. Identical filenames under different owners remain distinct lookup keys.

EmbeddedDataPresence distinguishes a metadata-only declaration, an explicitly authored empty data form, and nonempty encoded data. encoded_data() exposes the borrowed authored bytes; decode() performs bounded base64 and zstd decoding on demand. Malformed encoding, decompression overflow, and checksum mismatch are errors labelled with the resource name. They are never converted to absent data. KiCad's current and legacy seeded MurmurHash checksum forms and SHA-256 are accepted; an explicit empty payload does not require a checksum.

Standalone-footprint member parity

FootprintView exposes local pads, graphics, text/reference/value, text boxes, models, metadata, and embedded resources directly from a .kicad_mod. These records reuse the PCB source decoders and retain stable owner/index identity, source ordering, and source ranges. They do not fabricate a board occurrence or apply top/bottom occurrence transforms.

Pad records retain number and UUID evidence, authored net evidence, shape and custom polygons, local position/angle, layers, drills/slots/offset, plating, mask/paste margins and ratios, thermal and zone policies, and conditional-land fields. Footprint metadata retains local defaults, component classes, private layers, net-tie groups, and jumper groups. Unknown source forms remain governed by the existing source reader rather than being silently emitted as supported typed values.

Newstroke coordinate and placement contract

realize_newstroke_a0 accepts and returns KiCad source millimetres in a y-down coordinate system. It realizes the package's vendored KiCad Newstroke table, not a TTF outline approximation. Horizontal and vertical alignment establish the local baseline origin; italic shear is applied in local coordinates, followed by optional X mirroring, negative source-angle rotation, and translation. Unambiguously, source +90 degrees maps local +X toward global -Y. The returned bounds use placed millimetre coordinates; actual cursor advance and the Python-compatible pre-alignment width are reported separately because an unsupported glyph advances as ? but contributes no width to the legacy alignment calculation. Bounds cover centerlines only; consumers expand them by half the effective stroke width when stroke extents are required.

Each pen-down run is returned as one ordered NewstrokePolyline. Newstroke " R" pen-up markers split paths, so disconnected strokes are never joined. Authored thickness is returned unchanged. Without it, normal text uses one eighth of the effective X size and bold text one fifth, clamped to one quarter of the smaller nonzero text dimension; a fully zero-sized request retains the existing 0.15 mm fallback.

The supported source markup is ~{overbar}, _{subscript}, and ^{superscript}, including the existing nested-style rules. Unsupported codepoints are realized as ? and counted. This API deliberately retains the existing single-line realization behavior: newline is an unsupported glyph and uses that same fallback; it does not introduce multiline block layout.

Usage shape

let output = realize_newstroke_a0(
    NewstrokeRequest {
        text: "R_{sense}",
        position_x_mm: 10.0,
        position_y_mm: 20.0,
        size_x_mm: 1.0,
        size_y_mm: 1.0,
        angle_degrees: 90.0,
        horizontal_alignment: TextHorizontalAlignment::Center,
        vertical_alignment: TextVerticalAlignment::Center,
        mirrored: false,
        italic: false,
        bold: false,
        stroke_width_mm: None,
    },
    NewstrokeLimits::default(),
)?;
for path in &output.polylines {
    consume_centerline(&path.points);
}

Limits, evidence, and test ownership

Newstroke input bytes, parsed markup nodes, retained polylines, and retained points have independent inclusive ceilings. Invalid or derived-nonfinite geometry and resource exhaustion fail without returning partial output. Board bounds and dimension stroke geometry call the same realization engine, removing the previous duplicate glyph traversals while retaining the TTF render-cache path unchanged.

embedded_resource_slice owns owner scoping, payload-state, decoding, checksum, and malformed-data vectors. footprint_typed_slice owns standalone/embedded local-member parity and source identity. newstroke_geometry owns exact Python realizer oracle coordinates, pen-up splits, placement, widths, markup, fallback, and every public limit boundary. Existing board plotter, dimension, and resource-limit suites own shared-engine regression coverage.
