Rust Phase 4 native compiled graph semantics

Status: review ready. This vertical slice ports deterministic identity and graph-wide semantic validation. It does not yet claim project-byte parsing, connectivity compilation, or exact project-to-graph parity.

Identity allocation

CompiledGraphIdentityAllocator owns scope and selector normalization, canonical ASCII JSON, duplicate-address detection, and UUIDv7 byte formatting. It matches all shared source, derived, supporting, Unicode, precedence, normalization, and failure vectors. RustCrypto sha2 supplies only SHA-256, and unicode-casefold supplies Unicode full case folding; both sit behind package-owned APIs and work without native FFI. Canonicalization and allocation policy remain in-house. Their licenses, maintenance, and final feature topology remain part of the later dependency review rather than an implied public API commitment.

Semantic validation

Validation first applies the strict TypeSpec transport boundary, then builds each reference index exactly once. It validates RFC 4122 UUIDv7 row identity, uniqueness, typed references, definition and occurrence inverse ownership, hierarchy ownership, terminal/local/component page ownership, scalar hierarchy bindings, resolution completeness, and graphical target attribution.

Hierarchy cycle detection uses one color map and marks each unit occurrence visiting and done once. Runtime is O(rows + references), retained validation memory is O(rows), and no collection cross-product or repeated parent-chain walk is used. The validator borrows generated DTO strings and does not clone row payloads. Compiler input and output ceilings belong to the upcoming named source-bundle/compiler operation; this already-owned DTO validator does not invent a second arbitrary size policy.

Evidence and retained work

  • The native allocator consumes the same language-neutral vectors as Python, including Unicode canonicalization.
  • Focused Rust tests cover valid semantics, wrong reference types, inverse ownership, cycles, duplicate IDs, binding roles, and graphical target types.
  • Rack L3_018 sends all four reference-project graphs through the native strict and semantic validators in one sequential native process.
  • Package-owned unsafe code remains forbidden.
  • Named multi-file source bundles, schematic/project readers and writers, connectivity compilation, graph emission, and exact corpus differential output remain active Phase 4 work.
