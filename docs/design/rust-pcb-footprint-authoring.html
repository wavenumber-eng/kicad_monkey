Rust typed PCB and footprint authoring

Status: issue #84 typed authoring is independently reviewed and accepted through roots/setup, pad/via manufacturing, route/zone/fill cache, presentation, resource/model, and explicit support/gap tranches. The public API constructs new .kicad_pcb and .kicad_mod source from owned typed values. It does not require or replay an existing source string. Existing source-preserving document edits remain a separate API.

Supported source envelope and ownership

Read policy: accept modern KiCad 8, 9 and 10 source permissively. A source document may retain syntax that a particular typed projection does not yet expose; successful parsing is not a claim of complete semantic coverage. Source-preserving replay and fresh typed authoring remain separate operations. Unsupported authored semantics must never be silently discarded.

Fresh-write policy: target the selected released KiCad, currently 10.0.6, rather than the oldest readable format. Its board and standalone-footprint file revision is 20260206, as declared by the pinned 10.0.6 source. Release version and file revision are distinct; generator metadata continues to identify the actual producing tool.

Settled nightly features may be deliberately promoted before release. Each exception records the feature, authoritative source commit, required file revision, compatibility with the released reader, and a focused accepted vector. This is not blanket nightly support. Never stamp a released file revision over newer syntax that requires a higher revision. Line endings are a candidate for this policy, not an assertion of current writer support.

Implementation checkpoint: the writer still emits and accepts only 20241229. Migration to the selected 10.0.6 target is deferred under writer debt #87 while Appz canonical import/export progresses; changing the header alone is insufficient (net encoding, via types, island flags and pad-to-die scaling also changed). Existing 10.0.5 upgrade evidence does not qualify that new output target. The API ownership below is unchanged.

AuthoredPcb owns the board envelope and board members. AuthoredFootprint owns only a reusable local definition; AuthoredStandaloneFootprint owns its document revision, generator fields, default layer, and local definition. AuthoredFootprintOccurrence separately owns board layer, position, angle, occurrence UUID, lock state, and optional schematic placement path/sheet metadata. A standalone root therefore cannot pretend to carry a board occurrence UUID, document-envelope fields cannot be silently ignored by board placement, and repeated occurrences require distinct occurrence and member UUIDs.

UUID uniqueness compares identity values case-insensitively. Uppercase and lowercase hexadecimal spellings cannot register the same identity twice; unique caller spelling is preserved during emission.

Occurrence placement paths contain slash-separated UUIDs with a leading slash; they are schematic references, not filesystem locations. Malformed paths are rejected because KiCad can replace invalid UUID text with random identities. Explicitly empty path, sheet-name, and sheet-file values are rejected because KiCad drops them when saving. These fields never belong to the reusable local definition.

canonical_text() validates typed values and emits through the package S-expression builder. to_document() additionally reparses the complete candidate into PcbDocument or FootprintDocument before publication. Both owned documents expose bounded write_to(); the pre-existing PCB replay/edit path is unchanged.

First promoted families

The public board, embedded-footprint and standalone-footprint graphic readers preserve optional source net association, plural layer selectors (including an explicitly empty list), rectangle radius and local solder-mask margin. PcbGraphic.polygon_points carries ordered PcbPolygonPoint::Xy and Arc elements, without flattening. The existing points field is only an XY compatibility projection and is not complete polygon geometry. The same polygon element type is shared by pad primitives; PcbPadPolygonPoint remains a compatibility alias. These facts follow the released KiCad 10.0.6 parsePCB_SHAPE and parseOutlinePoints source at commit caf7377e9cb6fa1535ec3596dcb8c99bf44a996e. Read coverage is not fresh writer coverage: AuthoredGraphic currently cannot author nets, polygon-embedded arcs, rounded rectangles, plural layers or shape-local mask margins. Those explicit writer gaps belong to issue #87 and require checking the selected output revision before promotion. Existing document replay/edit retains source forms; consumers must not treat the XY-only compatibility view as a lossless rewrite path.

PcbGraphic.effective_fill_for_layer resolves omitted legacy fill using the KiCad 10.0.6 shape parser rules: zero-width rectangles/circles and polygons outside Edge.Cuts imply solid fill. The caller supplies a resolved concrete layer; the helper does not expand plural selectors, alter authored optional fill evidence, resolve unfilled stroke fallback widths, or reinterpret explicit hatch/other fill tokens. The graphic reader resolves legacy top-level width and modern stroke declarations in source order. Stroke blocks update only authored width/style fields; absent fields retain prior values. Initial width is zero. Present empty or nested-only fill/width values fail explicitly rather than being mistaken for omitted defaults.

Source reading is also separate from the existing public board plotter. Its polygon rendering still uses the XY-only compatibility projection, and rounded rectangles and plural layer selectors are not fully rendered there. Those pre-existing renderer limitations remain source-library integration debt under issue #84; these reader tests do not prove rendering parity. Native consumers requiring complete geometry must use the typed outline and inspect the optional physical fields.

The spike promotes explicit board thickness, paper, layer table, auxiliary and grid origins, physical stackup layers/material/electrical fields, outer profile and cutout graphics, nets, footprint occurrences, properties and user text with Newstroke source effects, non-text local artwork, basic and composite custom pads, round and slotted drills with offsets and plating implied by typed pad kind, board/footprint/pad mask-paste precedence and pad-local unused-layer policies, models, straight routes, three-point circular routes, and board/footprint embedded resources.

The writer preserves source vocabulary rather than introducing downstream PCB A0 geometry. It emits a caller-authored arc as KiCad start/mid/end, retains local footprint coordinates, and does not compose bottom occurrence transforms. Project companions continue to use ProjectDocument; this API neither replaces that writer nor publishes artifacts. Text effects expose width as size_x_mm and height as size_y_mm; emission follows KiCad's source ordering of (size height width).

Reference and Value are authored as footprint properties, matching the canonical form retained by current KiCad. AuthoredFootprintText is structurally user text; standalone pad net associations are rejected because KiCad drops board-net evidence when upgrading a library footprint. Board member layers must resolve through the authored layer table, and the first promoted token vocabularies reject values outside their documented KiCad spellings.

AuthoredPcb.properties owns board-root AuthoredProperty { name, value } strings, separate from graphical footprint properties and companion project settings. Empty strings are retained; duplicate exact names are rejected because KiCad stores this scope in a map and discards later duplicates. Emission neither resolves variables nor adds text-cache companion context; the existing unresolved-cache loss boundary remains.

Pads expose optional pin_function, pin_type and die_length_mm. Pin strings remain source vocabulary, not a new schematic pin-type rule catalog. Empty strings and standalone/library pin metadata are rejected because KiCad omits them on save. Pad-to-die length is an independent signed source value, not an inherited clearance: finite nonzero values, including negative values, are retained in both scopes; explicit zero is rejected because KiCad omits that default. This follows KiCad 10.0.6 parsePAD, format(PAD*) and the direct PAD::SetPadToDieLength setter at caf7377e9cb6fa1535ec3596dcb8c99bf44a996e.

Typed pad and via manufacturing tranche

Footprint attributes retain the source dnp token in both embedded and standalone ownership. The shared KiCad 10.0.6 footprint writer emits this attribute without an ownership restriction. This is source metadata, not a population decision for downstream canonical PCB models; appz retains its population-neutral boundary. Existing fresh and CLI readback assertions cover the source token without suppressing any footprint members.

Pad geometry now includes trapezoids and chamfered round rectangles in addition to the first-spike shapes. Typed pad policy fields cover local mask and paste margins, paste ratio, clearance, thermal bridge width/angle/gap, zone connection mode, forced zone layers, and plated-through-hole unused-land behavior. Chamfer corners are a closed enum, forced layers resolve to declared copper layers, and unsupported or contradictory combinations fail before emission.

Pad zone connection is a closed four-case enum: no connection, thermal relief, solid fill, or thermal relief for through-hole pads. These map to KiCad source values 0 through 3; out-of-domain integers are not constructible.

AuthoredFootprint::clearance_mm and zone_connect retain optional footprint defaults. An absent connection inherits; explicit zero clearance remains a value in the supported revision. Pad-local overrides remain independent. Legacy footprint thermal_width and thermal_gap are deliberately not authored: the KiCad 10.0.6 parser consumes and discards them. The raw source reader may retain that evidence, but it is not an effective thermal policy and cannot survive a KiCad save as such. Downstream exporters own reporting this representability loss; the source writer does not invent replacement pad rules.

A non-plated through-hole pad may explicitly author an empty layer list. The writer emits (layers), not an omitted declaration or inferred copper/mask layers, while retaining the required drill and its source offset. Empty lists remain unsupported for SMD and plated-through-hole pads; existing drill and net-association checks still apply.

AuthoredSetup::tenting_front and tenting_back retain effective board defaults. The writer emits an explicit setup clause, including an empty clause when both are false. Optional per-via settings remain separate and override the corresponding board side. This source policy is not inferred from plotted mask geometry.

This setup retention does not repair source plotting: current via mask exposure checks explicit via tenting only and does not inherit board defaults. The plotter follow-up is separately tracked from source reader/writer proof.

AuthoredPadstack and AuthoredViaStack support front-inner-back and custom source modes with typed Inner or copper-layer selectors. Parent pad/via geometry owns F.Cu; source rows describe Inner/B.Cu or specific remaining copper layers. Pad rows retain shape, size, land offset and optional local clearance/thermal/zone settings, including explicit inherited zone connection -1. Custom row geometry reuses the primitive writer; custom clearance is pad-wide, so layer rows require absent clearance policy. Via rows support circular diameters only.

Rows may be sparse. Absence uses KiCad's own defaults, and save may materialize missing rows, including all 32 copper slots for standalone custom pads. Fresh readback therefore pins authored rows, while post-save proof pins the source-normalized meaning rather than demanding an unchanged row count. Per-layer thermal bridge angle remains readable but fresh writing rejects it: the verified KiCad 10.0.6 parser temporarily applies it to F.Cu instead of the selected row, then overwrites F.Cu with the root angle or root-shape default after reading the pad. A fresh writer cannot promise the requested row angle. These are explicit source-loss boundaries, not a canonical padstack solver.

resolve_pad_copper_layer supplies a borrowed effective copper shape/policy view for native consumers. The raw PcbPadstack remains sparse authored evidence. Resolution follows released KiCad 10.0.6 PAD/PADSTACK defaults and const layer lookup: explicit non-front rows start with empty layer defaults, not root copies; absent custom rows fall back to the root. The front/inner/back lookup can use the Inner row for an absent back row. Offset/delta reset to zero on explicit rows. Root custom anchors default to circle; new row anchors default to rectangle. The helper neither selects present copper nor inherits footprint/design-rule policy, flips board sides, realizes geometry, or constructs another model. It rejects explicit front rows, duplicate rows, and unsupported selector aliases where sparse facts cannot faithfully describe ordered parser mutations. Authored row thermal angles are readable without blocking effective shape resolution: released 10.0.6 leaves non-front rows at their shape-default angle and retains the root override/default on F.Cu. The raw row values remain untouched for source evidence. This behavior follows parsePadstack and parsePAD, SetThermalSpokeAngle's default F.Cu target, and ThermalSpokeAngle's per-shape fallback. Zero-sized explicit rows remain zero-sized facts for the consumer to report or handle, not invented positive-area lands. This API targets modern source semantics; pre-7 custom-circle thermal-angle migration and arbitrary reordered pad fields are not an effective-parity claim.

AuthoredVia::backdrill optionally retains source diameter and ordered copper-layer endpoints, including a bottom-to-inner direction. This is not a fabrication constraint solver: KiCad's source form has no maximum-stub or stop-reference-mode fields. Exporting such canonical facts requires an explicit appz loss report or refusal, never silently treating an endpoint as proof of those constraints.

AuthoredVia owns diameter, drill, position, net, UUID, ordered copper endpoints, free status, front/back tenting/covering/plugging facts, capping/filling, forced zone layers, and unused-land policy. Through spans must be F.Cu to B.Cu; blind/buried spans must be partial; microvias must join adjacent declared copper layers. KiCad represents both blind and buried cases with the blind token and distinguishes them through their endpoints, which the typed API preserves.

Via net code 0 is the reserved typed representation for an unconnected via and needs no matching board net declaration. Positive codes must resolve to an authored board net; negative and unknown codes are rejected.

KiCad canonicalizes start_end_only no to absence and treats start_end_only yes as an alternative to the remove-unused/keep-end pair. The writer therefore rejects the lossy explicit-no form and conflicting mode combinations. Upgrading a 20241229 source in KiCad 10 also changes via connectivity from numeric to name-only net references; the independent proof resolves that name against the retained board net declaration.

Forced pad/via zone-layer connections require remove_unused_layers=yes; KiCad otherwise discards the requested layers during canonicalization. Pad layer lists and forced pad/via layer lists must also be unique because KiCad deduplicates repeated entries.

Custom-pad composition

AuthoredPadShape::Custom retains optional typed circle/rectangle anchor and outline/convex-hull clearance policies plus ordered line, three-point arc, circle, rectangle, polygon and cubic-curve primitives. Polygon outlines retain ordered XY and three-point arc elements; rectangles may carry a positive source corner radius. Coordinates remain pad-local, including under bottom/rotated occurrences. No primitive union, tessellation or downstream geometry conversion runs in this writer.

Every primitive has an explicit finite width. Closed primitives support solid, unfilled or absent fill declarations. Absence uses KiCad's source default: polygons fill, and zero-width circles/rectangles fill. Unfilled strokes must be positive because KiCad repairs nonpositive widths. Line, arc and curve fill declarations are rejected because KiCad's custom writer discards them. Hatch fills and non-solid stroke styles are not promoted. The compatibility CustomPolygon convenience delegates to the same emitter with a rectangular anchor, outline clearance and one zero-width solid polygon; new composition should use Custom.

The shared board/standalone reader exposes PcbPadPrimitiveGeometry and preserves the legacy polygon XY projection separately. Ordered polygon arcs and cubic control points are retained, not flattened; proxy bounding-box/vector shapes are distinguished from copper primitives. An incomplete or unsupported geometry returns None alongside its source record, not a fabricated empty shape. Raw fill tokens and ordered direct/nested width declaration decoding remain source evidence. This read boundary does not expand the plotter's custom-pad geometry support.

Source authority is KiCad 10.0.6 commit caf7377e9cb6fa1535ec3596dcb8c99bf44a996e: pad/shape parsing and custom primitive formatting. Existing native and independent-oracle cases exercise the composition; consumer mapping and full custom plotting remain separately qualified.

Presentation-source tranche

Fresh boards now own non-profile graphics, board text, and board text boxes. Footprint definitions own graphical Reference/Value properties, user text, text boxes, and local graphics independently of the occurrence transform. This preserves bottom-local layers and coordinates while a board occurrence separately owns its bottom/rotated placement.

Solid-filled circles, rectangles, and polygons may have zero stroke width in board or footprint scope. Negative/nonfinite widths are rejected. Unfilled graphics still require a positive width because KiCad replaces nonpositive unfilled strokes with its default; no replacement width is invented here.

Text effects distinguish an absent face (native Newstroke source intent) from a named outline-font face. Supported 20241229 effects include explicit width/height, optional thickness and line spacing, bold, italic, closed horizontal and vertical alignment, and mirroring. PCB/footprint color and hyperlink effects are rejected because KiCad 10 does not accept them in this source revision.

A named-font carrier can own the existing typed TextRenderCache, including multiple contours in one glyph polygon. The cache uses the package's existing bounded render-cache writer. Its text is realized display text: footprint property variables are resolved before validation, while cached board/project variables and wrapping-dependent text-box whitespace fail closed without companion outline-font context. A Newstroke carrier with a TTF cache is rejected instead of changing font semantics.

Standalone cache points are footprint-local. For a placed property or user text, board emission translates contours by the transformed carrier-anchor delta without rotating the glyphs, matching KiCad's cache frame. Locked footprint carriers in both standalone and board-embedded source use KiCad's keep-upright angle folded into (-90, 90]; unlocked carriers retain their local angle. A placed text-box cache instead rotates and translates contours with its geometry and adds the occurrence angle. Derived coordinates are checked for finiteness before emission. KiCad owns regeneration of outline-font caches during upgrade, so independent pre-upgrade evidence pins caller coordinates and post-upgrade evidence pins text, angle, finite contour geometry, and cache presence.

Board and embedded-footprint text-box locking is supported. KiCad 10 discards a locked flag while upgrading a standalone library footprint, so that specific request fails before emission. Boolean and ordering spellings for locked, unlocked, border, knockout, and text-box effects follow the accepted KiCad 10 writer/parser behavior for revision 20241229. Text-box geometry is a closed rectangle-or-polygon type, and margins are ordered left, top, right, bottom. Embedded text boxes retain local geometry only on an unrotated occurrence. KiCad 10 corrupts both polygon and start/end forms on a rotated occurrence across repeated saves, so that request is rejected. The unrotated polygon proof retains its exact local point chain through two CLI upgrades. Hidden user footprint text is also rejected because KiCad rewrites it as a generated property and changes its identity.

Resources and failure policy

AuthoredResourceData distinguishes declaration-only, explicit empty, and owned bytes. Byte payloads are compressed with zstd, encoded in KiCad's |base64| source form, and labelled with KiCad's current seeded MMH3-128 checksum. The same package decoder verifies exact readback. Input and aggregate encoded bytes have independent ceilings. Before doing resource work, the writer also checks a conservative aggregate allocation bound covering both the retained zstd buffer and base64 output.

Boards author resource payloads; standalone and embedded footprints author model references/transforms plus local resource declarations and payloads. KiCad 10 hoists an embedded-footprint payload into the board resource table during board normalization and leaves the footprint declaration as its lookup input; the independent oracle checks that exact relationship and payload bytes. A footprint declaration may intentionally reference a same-name board-owned payload. Because KiCad hoists footprint payloads into one effective board table, every repeated name across board and occurrences must have one resource type and at most one distinct payload semantics. Declaration-only references and byte-identical duplicate payloads are accepted; conflicting types, bytes, or empty/encoded presence fail before emission. A kicad-embed://NAME model requires a matching declaration of type model: local-only for standalone footprints and local or board scope for occurrences. Declaration-only entries remain valid lookup inputs because the host may supply bytes. Other model path schemes stay host-owned.

Companion project facts remain owned by the existing ProjectDocument API. Callers author supported text variables, netclasses, rules, and other accepted project paths there and stage its canonical_text() beside the PCB result. The PCB authoring API returns no implicit path, fetch, publication, or multi-file transaction.

Unsupported versions, invalid/nonfinite geometry, invalid or duplicate UUIDs, inconsistent net references, invalid pad/drill combinations, invalid custom polygons, duplicate resource names within an owner, object/point/ string/resource ceilings, and output overflow return structured source-build errors. No candidate document or partial source is published on failure. Types only expose promoted syntax; unrepresented families are explicit gaps, not fields silently dropped by a permissive serializer.

Usage shape

let mut board = AuthoredPcb::default();
board.layers = authored_layers;
board.nets.push(AuthoredNet { code: 1, name: "GND".into() });
board.footprints.push(AuthoredFootprintOccurrence {
    footprint: local_definition,
    layer: "B.Cu".into(),
    at: AuthoredPoint { x_mm: 40.0, y_mm: 30.0 },
    angle_degrees: 90.0,
    uuid: occurrence_uuid,
    locked: false,
    placement_path: None,
    placement_sheet_name: None,
    placement_sheet_file: None,
});
let document = board.to_document(PcbAuthoringLimits::default())?;
document.write_to(output)?;
let mut footprint = AuthoredStandaloneFootprint::new("Demo_Native", "F.Cu");
footprint.footprint.models.push(AuthoredModel {
    path: "kicad-embed://body.step".into(),
    offset_mm: [0.0; 3],
    scale: [1.0; 3],
    rotate_degrees: [0.0; 3],
});
footprint.footprint.embedded_files.push(AuthoredEmbeddedFile {
    name: "body.step".into(),
    file_type: "model".into(),
    data: AuthoredResourceData::Bytes(model_bytes),
});
let document = footprint.to_document(PcbAuthoringLimits::default())?;
document.write_to(output)?;

Evidence and retained work

pcb_authoring_slice constructs the complete first board and footprint proof from Rust structs, reparses them through native typed readers, verifies two same-Reference occurrences retain distinct occurrence/member identities, proves board/footprint/pad mask-paste precedence, checks exact payload bytes, and owns unsupported/loss and resource-limit vectors. Rack L1_039 invokes that writer independently, validates semantic relationships through the Python source model, and asks a resolvable KiCad CLI to upgrade both outputs. It reparses those upgraded files and reasserts the promoted source facts so a successful CLI exit cannot hide discarded input. The accepted local evidence used KiCad 10.0.5.

The consumer-completion extensions add existing-test assertions for footprint clearance/zone defaults, occurrence placement metadata, and explicit empty-layer NPTH in board and standalone source. Presentation assertions also cover zero-width filled board and local graphics. The L1_039/L1_040/L1_042 lanes check the corresponding facts after CLI upgrade.

The consumer-completion checkpoint passed the full locked core suite, strict Clippy, native/WASM no-default-feature builds and Rack L1_039 through L1_042, including source DNP, on installed KiCad 10.0.5. Appz exact-commit probes passed 48 frozen inputs and three real boards; this proves source API consumption, not full canonical import/export. The subsequent ordinary board group addition passed the full core suite, focused authoring assertions, strict Clippy, L1_039 independent read/save checks and independent review. Writer-target migration remains debt #87. These checks qualify the actual 20241229 output, not future 20260206 emission or a public release.

pcb_authoring_pad_via_slice adds exact native readback for trapezoid/chamfer/slot geometry, local fabrication and connection policies, through/blind/buried/micro spans, side-specific treatments, and both unused-land modes. Rack L1_040 repeats the semantic checks through the Python source model before and after a KiCad CLI upgrade, without depending on source member order.

The public zone reader keeps PcbZonePlacement.has_enabled separate from its boolean value: omitted enablement is not an explicitly disabled placement rule. Present enablement accepts only released KiCad yes/no syntax. The current zone polygon DTO carries XY coordinates only. Authored or filled zone contours containing arcs or unknown elements fail explicitly instead of being shortened; ordered zone arc support remains an importer/exporter coverage gap. Graphic/pad polygon readers have their separate ordered arc-capable carrier.

Authored zones retain source outline rings, per-layer filled-polygon cache chains, exact point order, and explicit island markers without classifying downstream topology. KiCad holes are bridge/fracture-encoded within one filled-polygon chain; a separate opposite-winding record is another positive outline, not a hole. Native and independent Python readback pin the emitted cache exactly. KiCad owns fill realization and recomputes those cache chains during a CLI upgrade, so the post-upgrade oracle reasserts authored zone intent and valid per-zone-layer refill output rather than claiming that KiCad preserves caller cache coordinates.

pcb_authoring_zone_slice also owns four source-identity-pinned clockwise/counterclockwise by minor/major three-point circular-arc vectors. Native and Python readers classify the authored triples geometrically, and Rack L1_041 repeats that classification after KiCad normalization rather than requiring one raw encoding.

The promoted zone intent includes closed none/edge/full outline hatch styles, closed thermal/no/solid/through-hole-only pad-connection modes, clearance, minimum thickness, priority, fill thermal settings, and the three island-removal modes. The 20241229 grammar only authors filled_areas_thickness no; an explicit yes request is rejected. Island minimum area is accepted only with minimum-area removal mode. Boards must declare an even copper-layer count, and reserved net code zero is supported for unconnected straight and arc routes as well as vias.

pcb_authoring_presentation_slice adds exact native readback for board and footprint graphics, Reference/Value and user-text effects, board and local text boxes, Newstroke source intent, and multi-contour TTF caches. Rack L1_042 repeats those semantic checks with the independent Python reader and KiCad 10. It accepts KiCad-owned outline-cache regeneration while requiring retained font, alignment, layer, transform, knockout, and carrier relationships. It repeats the board upgrade to catch non-idempotent text-box geometry drift.

pcb_authoring_slice additionally owns model transforms, exact resource bytes and presence states, same-name effective board namespace conflicts, declaration-only host lookup, and standalone-local versus occurrence-local/board model resolution. Rack L1_039 proves the corresponding KiCad 10 footprint-payload hoist and exact decoded bytes after upgrade.

Known fail-closed cases include unsupported source revisions; hidden user footprint text; rotated embedded text boxes; standalone text-box locking; malformed or explicitly empty occurrence placement metadata; zero-width unfilled graphics; empty-layer SMD or plated-through-hole pads; Newstroke carriers with outline-font caches; cached unresolved board/project variables; wrapping-dependent text-box cache requests; source-revision-invalid color or hyperlink effects; standalone pad net evidence; conflicting effective resource declarations; and embedded model paths without a matching model declaration. These are structured errors, not silently discarded fields.
