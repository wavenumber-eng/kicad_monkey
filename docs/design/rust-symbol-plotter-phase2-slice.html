Rust Phase 2 Symbol Plotter-IR Slice

Decision

Library-symbol bytes now produce the non-text body subset of kicad.plotter_ir.a0. Rectangles, circles, three-point arcs, polylines, and cubic Béziers reuse the same producer-neutral operations as footprints and future PCB and schematic readers. Pin shafts and all nine non-text pin decorations share those operations as well. Text and pin labels remain outside this slice so shaping can close through its own parity gate.

Source Selection And Semantics

  • The reader validates one kicad_symbol_lib root, scans only top-level symbol spans, and materializes only the uniquely named target.
  • Unit zero remains common to every requested unit. Style zero remains common to every style, and request style zero selects the normal style-one body used by the Python API.
  • Symbol Y-up millimetres become Y-down integer nanometres with ties-to-even rounding and JavaScript-safe-integer enforcement.
  • KiCad stroke defaults, explicit RGBA colours, line styles, fill enums, and fill-first/deferred-outline ordering match the Python producer.
  • Pin geometry covers line, inverted, clock, inverted-clock, input-low, clock-low, output-low, edge-clock-high, and non-logic styles. Hidden pins emit no operations, and arbitrary rotations remain deterministic.
  • A child with no body resolves its extends chain to the first base containing subsymbol geometry while retaining the requested child's header metadata. Missing bases and cycles terminate with empty geometry, matching the Python library renderer.

Contracts And Resource Bounds

TypeSpec owns the symbol request, result, document, record union, shared style fields, expanded fill vocabulary, and Bézier operation. Generated Rust, Python/msgspec, and TypeScript projections are committed. Semantic validation requires the lib_symbol header first and permits only layer-free body geometry in lib_subsymbol records; footprint graphics still require a layer and pad/drill states cannot cross into symbol output.

Source bytes, depth, library symbol count, subsymbol count, operation count, geometry point count, and output bytes are independently bounded. Every failure returns diagnostics with empty output. Browser callers use plotSymbolIr with separate source and request byte arrays.

Evidence And Retained Work

Rack L1_027 compares the exact body and all-style pin operation streams with the Python oracle, validates both the generated strict schema and established IR schema, and orchestrates native and host-adapter Rust tests. The real WASM suite covers successful pin geometry and fail-closed point limits. Rustfmt, warnings-denied Clippy, the wn-dev-std structural ratchet, the complete Cargo workspace, and deterministic contract generation pass.

Pin names and numbers follow through the Rustybuzz shaping and outline extraction gate. The inheritance slice resolves render geometry only; broader inherited source-model fields remain part of future typed model expansion.
