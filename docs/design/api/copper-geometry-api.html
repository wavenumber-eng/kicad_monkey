PCB Copper Geometry API

The kicad.copper_geometry.a0 contract is a projection-first, renderer-neutral representation of board copper and drill geometry.

KiCadCopperGeometryDocument

Rationale

Geometry consumers should not need a complete PCB parse, unrelated board graphics, or Plotter IR operation reconstruction to obtain copper.

Purpose

Own the versioned layer, net, polygon, drill, bounds, coordinate-space, tolerance, source, and diagnostic tables returned by emit_pcb_copper_geometry.

Test Requirements

Tests must validate the JSON Schema, deterministic serialization, supported copper families, v9/v10 net semantics, and projection/full-board parity.

Working Definition

The document is working when file inputs stay projection-first and every emitted ring uses unclosed integer-nanometre board-right/board-down coordinates with explicit outer and hole roles.

KiCadCopperFeature

Rationale

Copper polygon identity and connectivity must survive renderer adaptation.

Purpose

Represent one track, track arc, via, pad, or filled-zone polygon with document-local net/layer indexes and optional footprint/pad identity.

Test Requirements

Tests must cover family ordering, layer expansion, net indexes, holes, source identity, pad identity, and minimum ring validity.

Working Definition

A feature is working when its polygon and identity can be routed directly to clipping and selection without inspecting Plotter IR.

KiCadCopperDrill

Rationale

Hole caps and plated barrels require metadata beyond a polygon cutout.

Purpose

Represent via, plated-pad, and NPTH centers, oval dimensions, plating intent, layer span, and optional component identity.

Test Requirements

Tests must cover round and oval drills, offsets, plating, footprint transforms, layer spans, and NPTH behavior.

Working Definition

Drill metadata is working when downstream code can generate cap holes and barrels without returning to the PCB model.

KiCadCopperLayer

Rationale

Features need compact, deterministic layer attribution.

Purpose

Map a dense document index to a canonical KiCad copper-layer name while retaining source ordinal, type, user name, and optional stackup thickness.

Test Requirements

Tests must cover deterministic copper-only ordering, wildcard expansion, via spans, source ordinals, and valid feature/drill indexes.

Working Definition

The layer table is working when all geometry references dense indexes and consumers can recover canonical layer names without source parsing.

KiCadCopperNet

Rationale

KiCad 9 ordinal nets and KiCad 10 name-only nets need one contract.

Purpose

Map a dense document index to an authoritative net name with an optional pre-v10 source ordinal.

Test Requirements

Tests must cover ordinal resolution, name-only input, deterministic ordering, unconnected geometry, and valid feature indexes.

Working Definition

The net table is working when names preserve connectivity across KiCad versions and ordinals remain compatibility metadata only.

Explicit exclusions

The a0 contract excludes silk, fab, courtyard, text, images, mask/paste, component models, triangulation, tiling, mesh compression, and renderer-specific Clipper or GLB schemas.
