Rust native PCB reader/writer Phase 3 slice

Status: review ready. This slice begins native parity; it does not approve or expand WASM packaging.

Boundary

PcbView owns no source text and builds no generic S-expression tree. It borrows one UTF-8 board buffer, validates exactly one kicad_pcb root, and retains exact structural spans for direct board forms. Nested footprint, routing, and zone facts are decoded from their bounded source spans.

The first promoted families are layers, nets, top-level properties, footprints, nested pads and model references, segments, vias, and zones. Unknown top-level forms remain iterable and all untouched bytes survive focused edits.

Write behavior

The initial writer replaces one unambiguous top-level property value. It quotes through the shared deterministic builder, patches only the exact value token, applies an output ceiling, reparses semantically in tests, and requires a byte-stable second write.

Evidence

Native integration tests cover typed values, exact spans, preservation, absolute lazy diagnostics, and fail-closed source/family/nested/output limits. Rack case L1_029 builds a native executable and compares collection counts plus representative footprint and routing fields against the Python object model on the two promoted large boards.

Retained gates

This is not complete PCB parity. Additional graphics, arcs, groups, dimensions, embedded/generated content, mutation operations, and PCB plotter parity remain open. TypeSpec interchange contracts are required only before a boundary is made public. PCB WASM packaging remains later work, including the four explicitly deferred adapter gates from the native Phase 2 review.
