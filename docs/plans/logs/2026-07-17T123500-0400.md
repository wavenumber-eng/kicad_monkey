# Log: external-review (strict docs review of 6674ad6)

Strict independent review of the project workflow guide commit (`6674ad6`).
All example code was executed against the corpus; all internal links resolve;
`dev-std audit` and L99 (21 passed) were independently reproduced. Mechanics
are sound. The verdict below is findings-based, not a clean approval.

## Verdict

**Revise before this guide is cited publicly.** Three accuracy findings and
several tightening items.

## Blocking findings

1. **The projection wall-clock claim contradicts this plan's own baseline.**
   The guide says projection "saves time and memory by avoiding full typed
   board materialization." The fresh baseline (T104700) measured projection
   SLOWER than full parse for common-family inventories on both large boards:
   WREN 59.6 MB full parse 26.7s vs projection common 32.0s; 4-ch 28.1 MB full
   7.7s vs common 8.9s, nested 8.3s. Only narrow scans win (routes 20.0s vs
   26.7s; 4.1s vs 7.7s). The decision-table row recommending projection to
   "count large-board footprints, pads, ..." recommends the measured-slower
   path. Required fix: state that projection wins on memory and on narrow
   family scans; requesting several or nested families can cost as much as or
   more than a full parse.
2. **`nets` in the projection row lacks the v10 caveat.** KiCad v10 boards
   (`version 20260206`) have no top-level net table; `projection.nets()` is
   legitimately empty (name-only `(net "GND")` refs). Recommending projection
   for net counts without this caveat invites false bug reports. Drop `nets`
   from the row or add the caveat.
3. **Missing cost-intuition anchors.** The research review asked for concrete
   cost intuition in guidance. The cost-model column is purely qualitative.
   Add one short paragraph of measured anchors (e.g. 60 MB board: full parse
   ~27s, projection routes ~20s, projection common ~32s; `layers=` saves
   nothing), marked as indicative.

## Tightening items (non-blocking)

4. `design.save_json("build/design.json")` raises if `build/` does not exist —
   `save_json` is a bare `Path(path).write_text(...)`
   (`kicad_design.py:717-728`). Use a flat filename or add mkdir.
5. Decision-table row 1 merges netlist and design JSON, but `to_netlist()`
   never touches the PCB (schematic-only compile) while design JSON parses it.
   Split or clarify.
6. Idiom inconsistency: README counts routes with `sum(1 for _ in ...)`, the
   guide with `len(...)`. Getters return lists; pick `len(...)` in both.
7. The native-acceleration bullet in "Rules Of Thumb" is internal development
   planning inside a user-facing guide; move it to requirements/design docs.
8. The same guidance now lives in four places (README bullets, guide table,
   pcb-api and foundation-api cost models). Make the guide canonical and keep
   the others as short pointers to limit drift.
