# Log: documentation-guidance-audit

Audited README and design docs for guidance around full materialization,
source projection, targeted readers, IR, and SVG rendering.

## Findings

- README examples use `KiCadDesign.from_project_file(...).to_pcb_svg(...)` and
  `KiCadPcb.from_file(...).objects.where(...)` for inspection workflows. That
  is correct for rendering and mutation, but it gives performance-sensitive
  users no nearby example of `KiCadPcbProjection` or
  `iter_kicad_objects_from_file`.
- `docs/design/sexpr-projection-parser.html` clearly says projection is for
  narrow read-only scans and that full parsing remains the path for editing,
  round-trip, rendering, geometry, and netlist behavior.
- `docs/design/api/pcb-api.html` documents `KiCadPcbProjection` but does not
  present a decision table that tells users when to choose it instead of
  `KiCadPcb`.
- `docs/design/api/project-design-api.html` accurately describes `KiCadDesign`
  as an aggregate facade, but it does not warn that PCB access and PCB render
  helpers force full board materialization.
- `docs/design/api/foundation-api.html` documents `SexpSelector` and
  `SexpFormSpan`, but targeted reader usage is not prominent in README-level
  guidance.
- The docs do not currently explain that there is no named
  `KiCadSchematicProjection` while the generic targeted reader does support
  many schematic object classes.

## Recommended documentation changes

- Add README/API guidance titled along the lines of "Choosing the right read
  path": full OOP model for edit/render/write/netlist, source projection for
  large-board scans and diagnostics, targeted reader for selected typed forms.
- Add examples for model-reference inventory, route counts, and footprint/pad
  scans using `KiCadPcbProjection`.
- Add a generic targeted-reader example for schematic symbols or labels.
- Add explicit text that `KiCadPcb.to_ir()`, `KiCadPcb.to_svg()`,
  `KiCadDesign.to_pcb_ir()`, and `KiCadDesign.to_pcb_svg()` are full-model
  render paths today.
- Preserve the distinction between source projection and SVG/3D projection.
