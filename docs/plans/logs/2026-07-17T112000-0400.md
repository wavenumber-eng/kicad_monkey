# Log: api-design-decision

Independent review `2026-07-17T111500-0400` confirmed the research handoff and
authorized moving from research into the API decision step. This log records the
selected direction before durable design docs or implementation are edited.

## Decision summary

Accept documentation and guidance updates as the implementation path for this
plan. Do not add new file-level IR/SVG, inventory-helper, render-cache,
pull-parser, or native-extension APIs in this plan. Record the deferred parser
architecture and native acceleration work as future follow-up after the current
guidance and design documents land.

## Candidate decisions

1. **Documentation-only guidance: accepted.** The current public examples make
   the full-model path easy to find and make projection or targeted readers hard
   to discover. Durable docs should add a "choose the smallest correct read
   path" model with cost intuition.
2. **File-level inventory helpers wrapping `KiCadPcbProjection`: deferred.**
   `KiCadPcbProjection` already provides file-level PCB inventory entry points
   for footprints, pads, routes, zones, nets, models, and source spans. Add
   examples and guidance first; do not add thin helper names until a concrete
   repeated workload shows the current projection facade is still too hard to
   use.
3. **File-level IR/SVG helpers: rejected for this plan.** Current IR/SVG
   rendering needs full-board semantics for bounding boxes, draw order, layer
   filtering, zones, pads, holes, enrichment metadata, and stable output.
   `layers=` filters emitted records after full IR construction today; hiding a
   partial parse behind existing `to_ir()` or `to_svg()` would be misleading.
   Revisit only with a streaming typed parser or a separate reviewed render
   contract.
4. **Reusable render cache API: deferred.** Callers that render several views
   can already keep one loaded `KiCadPcb` and call render functions from that
   object. A supported Monkey cache would need invalidation, lifetime, memory,
   and mutation contracts. `kicad_cruncher` can keep its private per-run cache
   until a public Monkey cache has a concrete cross-caller need.
5. **Pure-Python pull parser or streaming typed parser: accepted as future
   architecture work.** Fresh decomposition shows token and generic-tree
   materialization dominate full parse cost. This is the first serious full
   parse lever because it avoids wheel and ABI costs while preserving the
   Python reference implementation.
6. **Native tokenizer/parser acceleration: deferred to a later plan.** Native
   acceleration must be a validated accelerator behind the Python reference
   contracts, not a fork. The raw regex scan number is harness-sensitive and
   should be treated as a bound, not a precise floor. Native work should be
   compared only after a pull-parser baseline exists.

## Durable-doc requirements

- Add an external-review evidence paragraph for PERF-REQ-008 in
  `docs/requirements/2026-07-17-performance-optimization-requirements.html`.
  Cite the fresh decomposition JSON and the independent review record so the
  prior performance requirements no longer rely on an uncommitted review log.
- Add README and design-doc guidance that explains cost intuition:
  full-model parse materializes the board; projection performs a full source
  scan plus selected hydration; targeted readers are appropriate for narrow
  object-family scans; render `layers=` filters output, not parse or IR-build
  cost.
- Document schematic narrow-read guidance through the generic targeted reader
  now. Defer a named `KiCadSchematicProjection` facade until a concrete
  source-span-preserving schematic workload justifies it.
- Keep `kicad_cruncher` work deferred until Monkey docs and decisions land.

## Validation impact

Minimum validation remains `uv run dev-std audit . --format json` and the L99
signoff lane. If any later edit adds public API behavior, the plan must add
focused L0 tests before moving past behavior signoff.
