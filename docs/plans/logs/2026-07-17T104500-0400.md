# Log: current-api-inventory

Inventory completed for the current public/provisional APIs relevant to full
materialization, source projection, project aggregation, IR, and SVG rendering.

## Full-model entry points

- `KiCadPcb(path)` and `KiCadPcb.from_file(path)` read the complete PCB text,
  call `from_string()`, run `parse_sexp()`, and then materialize the full
  `KiCadPcb` object graph through `from_sexp()`.
- `KiCadPcb.to_ir()` and `KiCadPcb.to_svg()` operate after a `KiCadPcb` is
  already materialized. They cannot recover parse-time savings for callers that
  already paid `KiCadPcb.from_file()`.
- `KiCadSchematic.from_file(path)` loads a full schematic and recursively
  attempts sub-sheet loads. `KiCadSchematic.to_ir()` and `.to_svg()` operate on
  that full schematic object.
- `KiCadDesign.from_project_file(path)` loads project JSON and the adjacent
  top schematic eagerly, records an adjacent PCB path, and parses the PCB only
  when `design.pcb`, `to_pcb_ir()`, `to_pcb_svg()`, design JSON PnP payloads,
  or other PCB-dependent paths touch it.
- `KiCadProject.from_file(path)` is project JSON metadata only and does not
  parse board or schematic source by itself.
- Symbol-library, footprint, worksheet, and plotter-IR `from_file` APIs remain
  full-file APIs for their respective source formats.

## Source projection and targeted reads

- `iter_sexp_file_form_spans(path, selector)` reads the text once and yields
  selected complete form spans without constructing the full token list, full
  nested tree, or typed document model.
- `iter_kicad_objects_from_file(path, object_type, ...)` maps selected spans to
  typed factories. It supports board objects, footprints, models, embedded
  files, full-file roots, and many schematic top-level objects.
- `KiCadPcbProjection.from_file(path)` reads the board text once and exposes
  PCB-family methods such as `footprints()`, `pads()`, `segments()`, `vias()`,
  `zones()`, and `model_references()`, with exact source metadata.
- There is no named `KiCadSchematicProjection` facade today. Schematic-side
  narrow reads exist through the generic targeted reader for classes such as
  `SchSymbol`, `SchWire`, `SchLabel`, `SchSheet`, and related schematic
  top-level objects.

## Terminology risk

The same word, "projection", appears in source projection and in visual
projection contexts. Source projection means selected S-expression source
spans. SVG/3D projection means visual or geometric rendering behavior. The
follow-on docs need to make that split explicit.

## Current conclusion

Existing code already has a useful narrow-read layer. The missing API surface
is not basic selected-object access; it is guidance, naming, and possibly
file-level render facades that make the right layer discoverable without
pretending current render methods are partial.
