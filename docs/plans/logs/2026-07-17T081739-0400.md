## Corrections to the primary research

1. **cProfile skews the recorded hot-path ranking.** Pure-Python scanner/lexer
   frames inflate 4-6x under the profiler while C-level `str.count`/dict work
   barely inflates. Example: the profile shows the 4-ch root-child scan at
   22.8s; wall-clock is 3.5s (7.79 MB/s, 10684 spans). In the profile txt the
   scanner looks dominant; in reality `str.count` is ~75% of the nested
   workload. Candidate selection must be gated on wall-clock micro-benchmarks,
   not the profile txt.
2. **`nets: 0` on 4-ch-backplane and speedy is real format behavior, not a
   parser bug.** Both are KiCad v10 boards (`version 20260206`); v10 removed
   the top-level net table and objects carry name-only refs like
   `(net "GND")`. Implications: issue #16 caching yields zero benefit on v10
   boards, and behavior tests need a v10 name-only fixture to lock `NetRef`
   fallback semantics.
3. **Per-span `span.parse()` cost (the char-by-char lexer) is underweighted.**
   The handoff lists it as "higher risk, needs review". Wall-clock, the lexer
   is the only lever for full parse (~80-90% of WREN's 44.4s) and the majority
   of WREN routes' 36.4s after the one-time root scan. It is the highest
   total-leverage candidate across all four probe operations.

## Recommended candidate priority

1. **#17 nested span rebase** - dominant on the worst observed workload
   (WREN nested 126.5s -> est. ~30-40s), low risk, best value-per-effort in
   the sweep. Land first. Prefer a per-file newline-offset index queried with
   `bisect` (O(log n) per query, trivially provable, reusable for any
   offset->line/column need); or arithmetic rebase with the index as the test
   oracle.
2. **Lexer rewrite (regex / `str.find` based tokenizer in `kicad_sexpr.py`)**
   - **the biggest single lever in the sweep; elevate out of "broader sweep"
   to a first-class dedicated slice.** It is the floor under everything:
   ~80-90% of full parse is lexing, and after the one-time scan, heavy
   projection hydration is mostly per-span re-lexing through the same
   `tokens()` path. The existing partial-parse machinery cannot help these
   workloads - it bounds how many bytes are lexed, not how fast; when
   hydration coverage approaches 100% (WREN common families 44.4s == full
   parse 44.4s), only lexer throughput matters. The same techniques also
   speed the span scanner's skip functions. Medium risk because it rewrites
   the most load-bearing code in the package - gate it on corpus round-trip
   goldens. Sequencing: land after #17.
3. **Single child-span scan per parent** (handoff's additional candidate) -
   real, cheap, ~8% on nested workloads.
4. **#16 net-map caching** - trivial and safe; include the double
   `net_name_by_ordinal()` fix. Expect ~3-6% on typical v8/v9 boards, more on
   net-dense boards, nothing on v10.

### Decision: pure Python first (user-confirmed 2026-07-17)

The lexer rewrite will be done as a **pure-Python rewrite first**; native
extensions or other implementation strategies are explicitly deferred and
only to be considered in the future. This matches the plan's non-goal ("no
native extensions ... unless the independent research gate shows Python-level
optimization is insufficient") and the standing kicad_monkey strategy of
keeping the Python toolkit as the reference implementation against a frozen
golden corpus. Expectation to record with the results: the realistic ceiling
for pure-Python lexing is roughly **3-8x** (compiled-regex tokenizer /
`str.find` delimiter jumps replacing per-char loops), e.g. WREN full parse
~44s -> ~8-15s. The measured post-rewrite numbers become the factual basis
for any future native-port discussion; that discussion is out of scope for
this sweep.

  (`kicad_pcb_projection.py:368-371`). Behavior tests should assert the span
  text actually corresponds to the matched pad (e.g. pad name at span start)
  so a factory-side reorder cannot silently misattach source metadata.

  `ec-performance-impact-recorded` should use >= 3 rounds.

  and `external-review` collide with step ids and break the `ec-` prefix
  convention used by the other criteria (audit passes today; style only).
- 4-ch-backplane and speedy are not public boards; keep WREN, jumperless, and
  synthetics as the citable public baselines per `ec-public-baselines`.
