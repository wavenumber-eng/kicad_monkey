# Log: independent-research-review

Independent review of the research handoff (`70a65f8`) by the same second
agent that reviewed the performance sweep. Verified research claims against
live code, checked the fresh measurements against prior independent
measurements, and audited the plan updates from the earlier plan review.

## Verdict

**Research confirmed; proceed to `api-design-decision`** with the additions
below folded in. The tentative direction (documentation/guidance first,
pure-Python pull-parser architecture as the first serious full-parse lever,
native acceleration only as a later validated accelerator, file-level render
APIs only as explicit new APIs or a recorded rejection) is endorsed.

## Claims verified against code

- `KiCadDesign.from_project_file` loads project + top schematic eagerly and
  parses the PCB lazily on first access (`kicad_design.py:285-291`,
  "parsing on first access"). Confirmed.
- `render_pcb_ir_to_svg` computes the all-layer bounding box first
  (`kicad_pcb_ir_svg.py:395`), builds the complete IR via `pcb_to_ir`
  (`:427`), and only then filters records by layer (`:454`). Confirmed - a
  `layers=` request does not reduce parse or IR-build cost today.
- The generic targeted reader registers schematic classes (`SchSymbol`,
  `SchWire`, `SchLabel`, buses, sheets; `kicad_targeted_reader.py:123-164`);
  there is no `KiCadSchematicProjection` anywhere in `src`. Confirmed.
- README contains zero mentions of `KiCadPcbProjection` or
  `iter_kicad_objects_from_file`. The docs-gap finding is real.
- Fresh Jumperless decomposition JSON reproduces this reviewer's prior
  independent measurement: identical match count (8,350,129), identical token
  count (5,236,594), `tokens()` 9.54s vs 9.52s, `parse_sexp` 11.65s vs
  11.67s. The materialization-floor conclusion is robust.
- The SWIG-deprecated / IPC-API-forward characterization of KiCad's binding
  direction matches this reviewer's prior reading of the KiCad dev docs and
  source tree.

## Corrections and additions required before the decision step

1. **Restore the dropped PERF-REQ-008 evidence fix.** The earlier plan review
   asked that `durable-design-doc-updates` add an "External Review Evidence"
   paragraph to
   `docs/requirements/2026-07-17-performance-optimization-requirements.html`,
   because the third (approving) review record of the perf sweep was never
   committed and PERF-REQ-008 currently asserts approval without a backing
   artifact. This item is absent from the corrections log and the plan. Fold
   it into `durable-design-doc-updates`; the fresh decomposition JSON now
   provides citable numbers for it.
2. **Cover all listed candidate directions in the decision.** Candidate #4
   (reusable render cache API for many views from one loaded board) and
   candidate #2 (file-level inventory helpers wrapping `KiCadPcbProjection`)
   are listed in the plan but not evaluated in any research log.
   `api-design-decision` must record an accept/reject/defer rationale for
   every listed candidate, not only #1/#3/#5/#6. Note: `kicad_cruncher`
   already has a private per-run render cache in its pcb-svg command; the
   render-cache question is whether Monkey should host a supported one.
3. **Treat the raw-scan number as a bound, not a precise floor.** The fresh
   measurement (1.119s) and this reviewer's prior measurement (2.08s) used
   the same match count but different Python loop overhead. The metric is
   harness-sensitive; the conclusion (scanning is a small fraction of the
   9.5s token cost) holds either way, but future comparisons should pin the
   harness or compare only like-for-like.

## Suggestions for the decision step (non-blocking)

- The "Choosing the right read path" guidance should include cost intuition,
  not only categories: projection = one full-file scan plus per-family
  hydration; full parse of a ~60 MB board is tens of seconds; `layers=` on
  render APIs filters output, not cost.
- The schematic answer worth considering: document the generic targeted
  reader as the schematic narrow-read path now; defer a named
  `KiCadSchematicProjection` facade until a concrete workload asks for
  source-span-preserving schematic scans.
