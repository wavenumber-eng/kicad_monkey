# KiCad Monkey 2026.8.18

Release version: `2026.8.18`

Date: 2026-08-18

This release delivers the bounded Windows-native application foundation through
the source-bound design-facts provider. The packaged `kicad-monkey-native`
process now exposes generated, versioned, resource-bounded transports for
compiled schematic graphs, deterministic version-E netlists, and base SVG.
Accepted Plotter-IR contracts remain frozen.

Cruncher's selected Windows paths use the public Monkey package without a
workspace dependency or Python fallback: PCB physical-base SVG serialization
and design-review compiled-graph/version-E artifacts are native, while Python
continues to own Design JSON, netlist JSON, SVG enrichment and presentation,
and command orchestration. Source snapshots, output identities, byte counts,
and hashes are validated before transactional publication.

Validation includes generated Rust/Python/TypeScript contracts, full native
and workspace suites, exact four-project graph/netlist parity, no-drawing pin
and multi-unit ordering regressions, bounded wildcard work, Rack composition,
and an isolated public-sdist-to-Windows-wheel two-package workflow.

The accepted Windows x64 release gate freezes the native and CLI contracts,
binds the content-addressed reviewed corpus prerequisite and four candidate
distributions to SHA-256 provenance, exercises the clean installed CLI without
a native override, and selects the tested Windows Monkey wheel and Cruncher
distributions for unchanged publication. Its corpus semantic/oracle evidence
is inherited from mandatory prerequisite gates; the candidate test itself runs
installed artifact smokes. The final promoted-tree candidate passed L3_027
1/1 in 67.38 seconds (68.38 seconds with Rack), and the complete build plus
gate took 192.6 seconds wall clock. The refreshed aggregate Rack report passed
7/7 subtests and 43/43 tests, including L99 23/23; three independent final
reviews approved closure. This is a single
immutable-candidate publication claim, not a claim that independent archive
rebuilds are byte-reproducible. Linux and macOS retain their Python providers.
