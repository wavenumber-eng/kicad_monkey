## External Review Follow-Up

External review found a high-severity stale-report issue in the new ERC hygiene gate: a failed `kicad-cli sch erc` process could leave a previous zero-violation JSON file in place, and KCR would parse that stale file while ignoring the failed process return code.

Fixed behavior:

- Delete the target ERC JSON path before invoking KiCad CLI.
- Require `kicad-cli` return code `0` for the ERC hygiene report to be `ok=true`.
- Treat missing ERC JSON after the invocation as failure.
- Keep parsing a JSON file when present so failure reports still include available diagnostics.

- `test_project_erc_hygiene_check_rejects_stale_json_when_cli_fails` writes a stale zero-violation JSON, runs a fake CLI that exits `7` and writes nothing, and asserts the report is `ok=false`, records return code `7`, removes the stale file, and reports the missing fresh JSON.
